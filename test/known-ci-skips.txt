# Test classes that skip at least one test on a bare CI runner, and why.
#
# Checked by tools/check-ci-skips.php against the JUnit log of the integration
# job. A class that skips and is NOT listed here fails the build by name; a
# class listed here that skips nothing prints as stale and should have its line
# deleted. Same contract as test/Fuzz/known-form-gaps.php: a subset comparison,
# so the file records accepted gaps and nothing else.
#
# The runner has no database, no production data, and no base schema to build
# one from — `database/` holds ninety incremental migrations and no full dump,
# and the capsule's data comes from a gitignored production export. So the
# overwhelming majority of these lines say "needs a database", and that is a
# permanent property of this repository rather than a task somebody forgot.
#
# What the file buys is the difference between 195 skipped tests and 195
# skipped tests *for reasons a human wrote down*. When a class stops running
# here — an extension goes missing, a container stops building, a skip guard
# gets added — its name appears in the failure instead of the count moving.
#
# Every entry below was confirmed against CI run 34202664497, and the first draft
# was wrong in two ways worth knowing about, because both are easy to repeat:
#
#   - four entries were guessed from filenames rather than measured. Three of them
#     (PreprocessorCreateSafetyTest, TemplatesCompileTest, TranslationCatalogWriteTest)
#     turned out to RUN on a bare runner, and the fourth had the wrong namespace.
#   - not every test class here is `SchoenstattTest\Integration`. PublicationLinkingTest
#     is `BooksTest\Integration`, and a baseline line naming a class that does not exist
#     exempts nothing while looking exactly like one that works. The checker now reports
#     that as `unknown` and fails on it, which is how the mistake was found.
#
# Keep the reasons specific: "needs a database" is fine, "environment" is not.
